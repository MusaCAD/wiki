Until today, Musa CAD's documentation lived in Markdown files in the source repository. They were accurate, but they were written for the people building Musa CAD, not for the people drawing with it. This wiki is for you, the person drawing.

## What is here

- **Get started:** installing Musa CAD on Windows, Linux and macOS, your first drawing step by step, a tour of the window, and a page for everyone coming from AutoCAD.
- **A page for every command and setting.** All 394 of them, with how to type it, where it is on the ribbon, what it asks first, and the release it arrived in.
- **Dynamic Input**, explained properly. Typing at the cursor is what sets Musa CAD apart from other 2D CAD programs.
- **Scripting and automation:** how programs and AI agents make finished drawings with Musa CAD.
- This **blog**, for releases and longer write-ups.

## How it keeps up

Musa CAD has had eight releases in four months. Documentation written by hand falls behind at that pace, so the wiki does not depend on anyone remembering to update it.

- The command and settings pages, the keyboard shortcuts and the ribbon map are **read from Musa CAD itself** every time the wiki is built. If a command is added or moved, its page follows.
- The pictures of drawings are **printed by Musa CAD** while the wiki is built, from example files you can download. If a release ever broke an example, the wiki would refuse to build until it was fixed.
- Every page says **which release it was checked against**, and whether it is complete, partial or not written yet. If a page falls behind, it says so at the top.

## What is still to come

Most command pages show only what Musa CAD reports about the command. The explanations are being written now, starting with the commands you use every day. The user manual and the tutorials follow. Each page tells you honestly how far it has got.

## How you can help

Every page has two links at the bottom: **Edit page** and **Report a problem with this page**. If something is wrong, unclear or missing, tell me. That is the fastest way to make this wiki better for the next person.
