Three ways, in the order most people should take them. All of them bundle Qt, so nothing else needs installing. All of them need a graphics driver with **OpenGL 4.5 Core**: Mesa on Intel and AMD has it, as does NVIDIA's driver; a driver without it gets a message at startup saying what was found and what is needed.

## From Flathub (recommended)

Updates arrive with the rest of your applications, and the package exists for both x86_64 and aarch64.

```sh
flatpak install flathub org.musacad.MusaCAD
flatpak run org.musacad.MusaCAD
```

If `flatpak` or the Flathub remote is new to your system, [Flathub's setup page](https://flathub.org/setup) has the two commands for your distribution.

### What the sandbox means

The Flatpak asks for no filesystem access. Every file dialog is the desktop's own, routed through the file-chooser portal, so the application sees the file you picked and nothing else. Three consequences:

- A drawing whose external references or images sit beside it offers to open its folder instead, so relative paths resolve. A DXF export that writes embedded images beside the DXF asks for the destination folder the same way.
- **Save As** keeps a name typed without an extension exactly as typed, because the portal grants that name.
- The command line needs an explicit grant to read a path it was not handed by a dialog:

```sh
flatpak run --filesystem=home org.musacad.MusaCAD --check ~/drawings/part.musa
```

Without `--filesystem=home` the same command answers `Cannot open file`.

### DWG in the Flatpak

The converter download works inside the sandbox (it has network access for exactly that). The converter needs an X11 display: under an X11 session it runs inside the sandbox; under Wayland the sandbox has no display, so it runs on the host through the Flatpak portal, which you allow once:

```sh
flatpak override --user --talk-name=org.freedesktop.Flatpak org.musacad.MusaCAD
```

The DWG Setup dialog says so when it needs it. A converter already installed on your system is used the same way with **Use a converter installed on the host**.

## The AppImage

One file that runs on any reasonably recent glibc Linux (x86_64), from the [latest release](https://github.com/MusaCAD/MusaCAD/releases/latest):

```sh
chmod +x MusaCAD-0.8.0-x86_64.AppImage
./MusaCAD-0.8.0-x86_64.AppImage
```

- It needs FUSE 2 to mount itself (`libfuse2` on Debian and Ubuntu). Without FUSE, set `APPIMAGE_EXTRACT_AND_RUN=1` in the environment and it extracts and runs instead.
- It runs natively on Wayland when you have a Wayland session (the Wayland platform plugins are bundled), and on X11 otherwise. On NVIDIA under Wayland, 0.7.0 and later ask for desktop OpenGL by name; earlier versions reported OpenGL missing there.
- It does not add itself to your application menu. Put it where you like; a desktop entry is yours to write.
- The headless command line works from it with no display at all, which makes it the right binary for scripts and servers:

```sh
./MusaCAD-0.8.0-x86_64.AppImage --plot part.musa part.pdf --paper A3 --landscape
```

## The Flatpak bundle

Each release also carries `MusaCAD-<version>.flatpak`, a single-file bundle for installing a specific version without Flathub, for example on a machine that is not on the network. It needs the KDE runtime it was built against, which `flatpak` fetches from Flathub if the remote is configured:

```sh
flatpak install --user MusaCAD-0.8.0.flatpak
flatpak run org.musacad.MusaCAD
```

Installed this way the application still checks Flathub for newer versions and says so in the status bar, but updates do not arrive by themselves.

## Check the install

```sh
flatpak run org.musacad.MusaCAD --version
./MusaCAD-0.8.0-x86_64.AppImage --version
```

Both print `Musa CAD 0.8.0`.
